# Contributing

Use Node 24. Run npm ci, npm test, npm run check, npm run build, and browser checks before opening a pull request. Add meaningful authorization/conversion/regression tests when changing those boundaries.

Keep public APIs schema-validated. Never trust the client to enforce permissions. Do not introduce eval-based formula execution, arbitrary external imports, paid-only dependencies, proprietary source, copied branding, or undisclosed telemetry.

Prefer MIT, BSD, ISC, Apache-2.0, and equivalent permissive licenses. Inspect transitive dependencies and regenerate notices after changes. Do not assume a vendor's entire product has the license of its open-source core.

Contributions are licensed under Apache-2.0. Only contribute work you have the right to license. Use synthetic or legally redistributable fixtures.

Open issues with steps to reproduce, expected behavior, actual behavior, and a non-sensitive example. Security issues belong in a private report once that channel is configured.
